# 解决问题训练站 · 使用说明

一个纯静态的解题能力训练站。目标是让"解决问题"变成一件**可以验收**的事：
不只"读过"，而是**应知 → 应会 → 深度理解 → 迁移**四层全部通过。

---

## 〇、在线地址

**https://solve-lab.cn/**

## 一、怎么打开

### 方式 A：直接双击（最简单）
双击 `index.html` 即可在浏览器中打开，所有功能都能用。

> 提示：极少数浏览器在 `file://` 协议下会限制本地存储。
> 如果发现"保存的练习记录不见了"，请改用方式 B。

### 方式 B：起一个本地服务器（推荐）
在本文件夹里打开终端，执行：

```bash
python3 -m http.server 8000
```

然后浏览器访问 `http://localhost:8000`。

## 二、怎么分享给别人 / 发布上线

> 🚀 **本站是纯静态站：整个文件夹就是网站根目录，丢到任意静态托管上即可上线**（不需要后端、不需要数据库）。
> 目前的实际部署是**双 origin、同一个域名**：国内走 **华为云 OBS ＋ CDN**，国外走 **GitHub Pages**，都服务 `https://solve-lab.cn/`。



因为站点是纯静态的，**不需要后端、不需要数据库**，部署非常省事：

| 平台 | 做法 | 费用 |
|---|---|---|
| **华为云 OBS**（本站国内用） | 建桶 → 开**静态网站托管**（首页 `index.html`、错误页 `404.html`）→ 上传整个文件夹 → 挂 CDN 并开智能压缩 | 存储几元/月 ＋ CDN 流量 |
| **GitHub Pages**（本站国外用） | 建仓库 → 上传文件 → Settings → Pages → 选主分支根目录 | 免费 |
| **Vercel** | 拖拽整个文件夹到 vercel.com/new | 免费（Hobby 方案） |
| **Netlify** | 拖拽文件夹到 app.netlify.com/drop | 免费 |
| **腾讯云 COS / 阿里云 OSS** | 建存储桶 → 开静态网站 → 上传 | 几元/月 |
| **任意虚拟主机** | 整个文件夹丢进 www 目录 | 视主机 |

> 若要使用中国大陆的服务器（华为云/腾讯云/阿里云等），需要完成 **ICP 备案**（通常 1–20 个工作日）。
> 想立刻上线、不想备案，优先选 Vercel / Netlify / GitHub Pages。

> ⚠️ **双 origin 的两条硬要求**（本站用「国内华为云 ＋ 国外 GitHub Pages」时踩得到）：
> ① **两个 origin 必须同时更新** —— 页脚的版本号就是判据，两边不一致时用户会看到新旧混排；
> ② **静态资源要带版本号或短缓存** —— `assets/` 下的路径是裸路径（无 `?v=`），务必给 HTML 设短缓存、给 `assets/` 设长缓存并在升级时改名或加查询串。

## 四、怎么改内容

| 你想改什么 | 改哪里 |
|---|---|
| 章节名称、简介、顺序 | `assets/data.js` 里的 `PSC_CHAPTERS` |
| 自测题目、答案、解析 | `assets/data.js` 里的 `PSC_QUIZ` |
| 五步的操作定义、产出物 | `assets/data.js` 里的 `PSC_STEPS` |
| 错误归因清单（错误池 32 条） | `assets/data.js` 里的 `PSC_ERROR_DETAIL` |
| 导航栏分组 | `assets/data.js` 里的 `PSC_NAV` |
| 章节正文 | 对应的 `chapter-*.html` |
| 配色、字号、打印样式 | `assets/style.css` |

`data.js` 是全站的数据中枢：改一处，首页、导航、自测、进度表会同步更新。

## 五、数据存在哪里

- 所有数据（进度、练习库、日志、成绩）保存在**浏览器 localStorage**，不上传任何服务器。
- 换设备、换浏览器、清理缓存都会丢失 —— 请用 `progress.html` 的**导出／导入**功能迁移。
- 想清空重来：`progress.html` → 清空全部数据。

## 七、部署前必做：改成你自己的联系方式

本站把"评论与分享"换成了更轻的方案：**把钩子留在页面上**。
相关的联系方式集中在 `assets/data.js` 顶部的 `PSC_SITE` 里，**改这一处，全站生效**：

```js
const PSC_SITE = {
  name:'解决问题训练站',
  email:'you@example.com',                    // ← 改成你的邮箱；留空则不显示邮件入口
  github:'https://github.com/zxdxs/problem-solving-coach',   // ← 改成你的仓库；留空则不显示协作入口
  community:'',                                // ← 社群/公众号说明，可留空
  maintainer:'（请在此填写你的署名）'
};
```

`contact.html` 会读取这份配置，并做三件事：

1. **分享** —— 一键复制网址，或复制预设的推荐语（短版／长版）；
   还能把你的练习成果（掌握度、执行单份数、自测等级）生成一段可粘贴的文案。
2. **联系** —— 生成 `mailto:` 链接或 GitHub Issue 链接，
   并且**自动把你当前的练习数据填进正文**，让反馈更有针对性。数据由访客自己发出，网站不上传。
3. **共建** —— 列出三种参与方式（挑错／出题／写章节）与"改哪个文件"的对照表。

> 未配置时，联系页会显示占位提示而不是假链接，不会误导访客。

## 八、为什么不做评论区

- **技术上**：评论区需要服务器与数据库，一加就不是零成本静态站了。
- **体验上**：第三方评论插件加载慢、有广告，会毁掉这个站最值钱的东西——专注。
- **内容上**：这个站教的是"想清楚再动手"。用邮件和 Issue 代替评论区，反馈质量高一个量级。

日后若确实需要多人互动（学习小组、互评），升级路径见下一节。

## 九、以后想加"账号登录"怎么办

按渐进路线走，成本最低：

1. **现在**：静态站 + 本地存储 + 导出导入 JSON（已完成，成本 0 元）。
2. **验证有人用之后**：接 [Supabase](https://supabase.com) 的 Auth + Postgres。
   免费层含 5 万月活用户、500MB 数据库，对教学站通常够用。
   页面结构完全不用改，只需把 `assets/app.js` 里的 `read/write` 两个函数
   从 localStorage 换成 Supabase 的接口调用。
3. 若坚持自建后端：腾讯云轻量服务器约 ¥100/月（新人首年常有 ¥38–99 的优惠），
   但要自己负责鉴权、备份、安全与 ICP 备案。

**先让内容被人看到，再谈账号。**
