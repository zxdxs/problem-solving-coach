联系与共建

本站是纯静态的，没有账号、没有评论区。但分享、联系、共同维护这三件事， 我们换了一种更轻的方式来实现——把钩子留在页面上，把数据交还给你自己。

这一页做什么
  1. 分享：把这一站或你的练习成果发出去
  2. 联系：给维护者写信（自动带上你的进度）
  3. 共建：三种参与方式，从挑错到写章节
  4. 为什么不做评论区

一、分享

① 分享这一站

把网址复制走，贴到任何地方。对方打开就能用，不用注册、不用装东西。

② 分享我的练习成果

把你练了多少、掌握到什么程度，生成一段可直接粘贴的文字。 数据来自你自己浏览器里的记录，不上传任何服务器。

二、联系维护者

因为没有后端，联系走邮件和 GitHub Issue。两种方式都会自动带上你当前的练习数据—— 这样你不用解释自己练到哪一步，我这边也能给出更有针对性的回复。

邮件里会自动附上这些信息 你的总体掌握度、已完成章节、练习库条数、最近一次自测等级，以及你使用的设备与浏览器。 除此之外不会收集任何东西——因为这些内容是你自己发出去的，不是网站偷偷上传的。

三、共同维护

这个站点最需要的不是赞美，是这三件事。门槛从低到高：

你的名字会被记住 凡是贡献被采纳，你的名字（可用昵称）与具体贡献， 都会出现在贡献者名单里，长期保留。

① 挑错与建议

发现错别字、讲得不清楚、题目有歧义、某句话让你卡住了—— 直接开个 Issue 或写信。最低门槛，也是最有用的贡献。

② 补充题目

自己出一道好题（尤其是真实工作／生活场景题），连同答案和解析一起发过来。 站内的场景题都是这么来的。

③ 写章节 / 做翻译

把骨架章节扩成详填版，或翻译成其他语言。 可先读延伸阅读，了解这套方法的来龙去脉。

协作流程

  1. Fork 仓库到你自己名下
  2. 改你要改的文件（建议先从小处开始，比如加一道题）
  3. 提交 Pull Request，说明改了什么、为什么
  4. 合并后即发布——静态站没有复杂的构建步骤
共建前请先读这一段 贡献内容请自己写。例题优先选用经典问题，或用你自己的真实工作场景来设计。 更详细的说明见延伸阅读。

四、为什么不做评论区

这不只是技术取舍，也和内容有关：

  • 技术层面：评论区需要服务器和数据库，一加上就不再是零成本、零维护的静态站了。
  • 体验层面：静态站的评论区（Disqus、Gitalk 之类）要么加载慢、要么满是广告， 反而会毁掉这个站最值钱的东西——专注。
  • 内容层面：这个站教的是"想清楚再动手"。评论区最不缺的就是没想清楚就发出去的意见。 用邮件和 Issue 代替，反馈质量会高一个量级。

如果日后真的需要多人互动（比如学习小组、作业互评），再考虑加账号系统。 但那是以后的事——先让内容被人看到。
